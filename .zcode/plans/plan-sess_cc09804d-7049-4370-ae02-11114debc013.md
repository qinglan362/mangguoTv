## 目标

分析看板「高频关键词」板块改用 LLM 精选关键词（合并同义/变体词、剔除泛化无信息量词、聚焦舆情重点）。**只改看板这条链路**：报告（`report_service.py`）、前端其他板块、其余功能一律不动。

## 改动内容

### 1. `Django/dashboard/services/query.py`

- 把 `top_keywords()` 内的计数逻辑抽成私有函数 `_keyword_counter(topic_ids, start, end)`（LLM 每帖高频词聚合 + jieba 分词统计 + 排除主题配置词，行为完全不变）；`top_keywords()` 改为基于它取 top-N，**签名与行为不变**，报告继续用它。
- 新增 `top_keywords_refined(topic_ids=None, start=None, end=None, limit=30)`：
  1. 先查 Django cache（key 由 topic_ids/start/end/limit 组成，TTL 10 分钟），命中直接返回，避免每次刷新看板都调 LLM；
  2. 取候选词 `_keyword_counter().most_common(120)`；候选数不多于 limit 时直接返回统计结果，不浪费 LLM 调用；
  3. 构造 prompt：监测主题名 + 候选词及次数，要求 LLM 合并同义/上下位变体、剔除「感觉/真的/可以」这类无信息量泛化词，选出最能代表当前舆情焦点的 ≤limit 个关键词，以 `{"keywords":[{"keyword":"...","count":合并后次数}]}` JSON 输出；
  4. 调用 `analysis.services.llm.chat()`（复用全站 DeepSeek 后端与 Key，未配置 Key 或失败返回 None）；
  5. 解析并清洗结果（keyword 转非空字符串、count 转正整数、非法项丢弃），LLM 结果为空或解析失败时**静默降级**为统计结果，保证看板始终有产出（与报告摘要、观点抽取的降级风格一致）；
  6. 写缓存并返回。

### 2. `Django/dashboard/views.py`

`top_keywords` 视图（第 59 行）改调 `q.top_keywords_refined(...)`，URL、请求参数、响应结构 `[{keyword, count}]` 均不变。

### 3. `Django/dashboard/tests.py`

新增测试类覆盖：
- LLM 不可用（chat 返回 None）时降级返回统计结果；
- LLM 返回合并后的精选词时输出该结果（mock `chat`）；
- 缓存命中时不重复调用 LLM（mock 调用计数）；
- 原 `top_keywords()` 行为不受影响。

## 不改动

- 前端（`Dashboard.vue` / `WordCloud.vue`）：接口与数据结构不变，无需改动。
- `reports/services/report_service.py`：继续调用原 `top_keywords()`。
- 其他所有板块与功能。
